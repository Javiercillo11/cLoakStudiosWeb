CLOAK STUDIO — Web comercial y plan de implementación

Dominio: https://cloakstudio.app
Proyecto: Web comercial de Cloak Studio
Versión: 1.0
Objetivo principal: convertir visitas de negocios en solicitudes de presupuesto cualificadas.

> Este documento complementa `cloak-studio-brand-guide-claude-code.md`. Si existe una discrepancia, conserva la identidad y los tokens del brand guide anterior y aplica este documento a la estructura comercial, servicios y formulario.

────────

1. Objetivo del sitio

Construir una web comercial moderna, rápida y responsive para presentar tres servicios:

1. Páginas web para negocios — diseño y desarrollo de webs profesionales.
2. Aplicaciones de gestión para negocios — software adaptado a procesos empresariales.
3. QR para reseñas — códigos QR personalizados que facilitan el acceso de los clientes a la página de reseñas del negocio.

La web debe explicar claramente el valor de cada servicio y facilitar que el visitante solicite información o presupuesto seleccionando el servicio que le interesa.

Público objetivo

• Comercios y negocios locales.
• Autónomos y profesionales.
• Pequeñas y medianas empresas.
• Negocios que necesitan digitalizar o automatizar procesos.

Conversión principal

Envío correcto del formulario de contacto.

Conversiones secundarias

• Clic en CTA de servicios.
• Clic en email o contacto directo, si se configura.
• Visita a los detalles de cada servicio.

Título:
Soluciones digitales para hacer crecer tu negocio.

Descripción:
Diseñamos y desarrollamos herramientas digitales que resuelven necesidades reales de tu negocio.

Mostrar tres servicios en tarjetas coherentes, cada una con icono, número, título, descripción, lista breve de beneficios y CTA.

Servicio 01 — Página web para negocio

Nombre visible: Páginas web para negocios
Slug sugerido: web-para-negocios

Descripción:
Una web profesional que transmite confianza, presenta tus servicios y ayuda a convertir visitas en nuevos clientes.

Beneficios:

• Diseño adaptado a la identidad del negocio.
• Experiencia responsive para móvil, tablet y escritorio.
• Estructura preparada para SEO.
• Formularios y llamadas a la acción.
• Rendimiento y accesibilidad cuidados.

CTA:
Quiero una página web

Icono sugerido: monitor o panels-top-left.

Visual sugerido: mockup de una web de negocio en portátil y móvil. Usar una demo conceptual, no presentarla como cliente real.

Servicio 02 — Aplicaciones de gestión

Nombre visible: Aplicaciones para gestionar tu negocio
Slug sugerido: aplicaciones-de-gestion

Descripción:
Aplicaciones a medida para organizar el día a día de tu negocio, centralizar información y automatizar tareas.

Posibles funcionalidades, sujetas a análisis:

• Gestión de clientes.
• Citas y reservas.
• Empleados y roles.
• Inventario y productos.
• Pedidos y tareas.
• Informes y paneles de control.
• Automatización de procesos.

CTA:
Quiero una aplicación

Icono sugerido: layout-dashboard o workflow.

Visual sugerido: mockup de dashboard de gestión con datos ficticios claramente usados como demostración, nunca como resultados reales de un cliente.

Servicio 03 — QR para reseñas

Nombre visible: QR para conseguir reseñas
Slug sugerido: qr-para-resenas

Descripción:
Facilita que tus clientes lleguen a tu página de reseñas con un código QR personalizado para tu negocio.

Beneficios:

• QR personalizado con la identidad visual del negocio.
• Acceso directo al enlace de reseñas proporcionado por el cliente.
• Material preparado para imprimir o mostrar en el establecimiento.
• Instrucciones sencillas para colocarlo y utilizarlo.

CTA:
Quiero mi QR de reseñas

Icono sugerido: qr-code.

Importante:

• No prometer reseñas positivas ni un número determinado de reseñas.
• No incentivar reseñas falsas, filtrarlas por valoración o incumplir las políticas de la plataforma de reseñas.
• El QR debe facilitar el acceso a la página de reseñas, sin manipular la opinión del cliente.
• Solicitar el enlace real del perfil o página de reseñas antes de generar el QR final.

Comportamiento de las tarjetas

• Toda la tarjeta puede ser clicable si se implementa correctamente con semántica accesible.
• CTA visible y consistente.
• Hover discreto: borde violeta suave, elevación mínima o cambio de icono.
• En móvil, no depender de hover.
• Cada CTA debe llevar al formulario con el servicio correspondiente preseleccionado.

8. Formulario de contacto inteligente

Objetivo

Recoger solicitudes cualificadas y conocer el servicio que necesita el visitante antes de responder.

Título y texto

Título:
Hablemos de tu proyecto.

Descripción:
Cuéntanos qué necesitas. Revisaremos tu solicitud y nos pondremos en contacto contigo para hablar de los siguientes pasos.

Campos comunes

1. Servicio que te interesa — obligatorio, select o tarjetas seleccionables.
2. Nombre — obligatorio.
3. Nombre del negocio — opcional.
4. Email — obligatorio, validar formato.
5. Teléfono — opcional.
6. Cuéntanos sobre tu proyecto — obligatorio, textarea.
7. Aceptación de privacidad — checkbox obligatorio, sin preseleccionar.

Opciones del selector:

• Página web para negocio.
• Aplicación de gestión.
• QR para reseñas.
• Otro / No estoy seguro.

El servicio puede llegar preseleccionado desde las tarjetas de la sección de servicios.

Campos dinámicos por servicio

Cuando cambia el servicio, mostrar un pequeño bloque contextual. No borrar los datos comunes ya introducidos.

Si selecciona “Página web para negocio”

• ¿Tienes una web actualmente? — Sí / No / Necesita renovación.
• Tipo de negocio — texto opcional.
• ¿Qué necesitas? — Web informativa / Web con reservas / Catálogo / Tienda online / Otro.
• URL actual — opcional.

Si selecciona “Aplicación de gestión”

• ¿Qué necesitas gestionar? — Clientes / Citas y reservas / Empleados / Inventario / Pedidos / Otro.
• ¿Cuántas personas la utilizarían? — Solo yo / 2–5 / 6–20 / Más de 20 / No lo sé.
• ¿Utilizas actualmente alguna herramienta? — texto opcional.
• ¿Qué tarea te gustaría simplificar? — textarea opcional.

Si selecciona “QR para reseñas”

• Nombre del negocio — obligatorio para este servicio.
• Enlace a la página de reseñas — obligatorio antes de generar el QR; en el formulario puede ser opcional si aún no lo tiene.
• Plataforma — Google / Tripadvisor / Facebook / Otra / No lo sé.
• ¿Dónde utilizarás el QR? — Mesa / Mostrador / Cartel / Tarjeta / Otro.

Si selecciona “Otro / No estoy seguro”

• Mostrar solo el campo de descripción y permitir explicar la necesidad.

UX del formulario

• Actualizar campos dinámicos sin recargar la página.
• Indicar claramente qué campos son obligatorios.
• Mantener los valores al cambiar de servicio cuando sea posible.
• Validación inline, accesible y con mensajes concretos.
• Desactivar el envío mientras se procesa.
• Mostrar estado de éxito solo tras confirmación real del servidor.
• Mostrar error recuperable si el envío falla.
• No perder los datos escritos si ocurre un error.
• En móvil, campos a una columna; en desktop, dos columnas para campos cortos.
• Botón final: Enviar solicitud.
• Microcopy: Tus datos se utilizarán únicamente para gestionar tu consulta, de acuerdo con la política de privacidad.

Privacidad y seguridad

• Añadir enlace a la política de privacidad real.
• No inventar razón social, dirección, NIF, email ni texto legal definitivo.
• El checkbox no debe venir marcado.
• Implementar protección anti-spam razonable (honeypot y rate limiting; CAPTCHA solo si hace falta).
• Validar datos tanto en cliente como en servidor.
• Sanitizar y limitar longitudes.
• No exponer claves o credenciales en el frontend.
• No enviar datos personales a servicios de terceros sin informar y configurar adecuadamente el tratamiento.

Envío del formulario

Antes de implementar, inspeccionar el proyecto y detectar si ya existe backend, proveedor de email o servicio de formularios.

Si no existe:

• Crear una capa de envío desacoplada.
• Preparar variables de entorno documentadas.
• No fingir que el formulario envía emails si no está conectado.
• Durante desarrollo, usar un modo de prueba claramente identificado.
• Proponer integración de email (por ejemplo, proveedor SMTP o API transaccional) y pedir los datos/credenciales al propietario antes de activar producción.
• Añadir protección contra doble envío.
• Guardar solo la información necesaria y definir un proceso de conservación adecuado.

Contenido del email de notificación

Asunto sugerido:
Nueva solicitud desde Cloak Studio — {servicio}

Incluir:

• Servicio seleccionado.
• Nombre y negocio.
• Email y teléfono si se facilitó.
• Descripción.
• Respuestas dinámicas del servicio.
• Fecha de recepción.

No incluir secretos, tokens ni datos innecesarios.

Mensaje de confirmación

¡Gracias por contactar con Cloak Studio! Hemos recibido tu solicitud. Revisaremos la información y nos pondremos en contacto contigo.

Solo mostrarlo después de que el backend confirme la recepción.

11. Requisitos técnicos para Claude Code

Fase 0 — Inspección

Antes de tocar código:

1. Inspeccionar repositorio, package manager, framework y estructura.
2. Leer el brand guide anterior.
3. Identificar componentes existentes, estilos, formularios y backend.
4. Revisar scripts disponibles para lint, test y build.
5. Presentar un plan breve antes de implementar.
6. Mantener convenciones existentes y evitar reescrituras innecesarias.

Fase 1 — Sistema visual

• Centralizar tokens de color, tipografía, radios, sombras y espaciado.
• Implementar botones, inputs, select, textarea, checkbox y tarjetas de servicio.
• Crear estados hover, focus, disabled, loading, success y error.
• Reutilizar el logotipo SVG de Cloak Studio si ya existe; si no, crear una propuesta SVG original siguiendo el brand guide.

Fase 2 — Landing page

• Implementar header y navegación responsive.
• Crear hero.
• Crear sección de servicios con tres tarjetas.
• Crear sección de proceso.
• Crear sección sobre Cloak Studio.
• Crear CTA y footer.
• Asegurar que los CTA de servicios preseleccionan el servicio correspondiente en el formulario.

Fase 3 — Formulario

• Crear estado tipado del formulario.
• Implementar selector de servicio.
• Renderizar campos condicionales según el servicio.
• Validar cliente y servidor.
• Gestionar estados de envío y resultado.
• Conectar proveedor de email solo cuando haya configuración real.
• Documentar variables de entorno en .env.example, sin valores secretos.

Fase 4 — Calidad

• Comprobar responsive en móvil, tablet y desktop.
• Probar todos los servicios y cambios de selección.
• Probar validación de campos obligatorios y formatos.
• Probar envío correcto, error de servidor y doble clic.
• Comprobar navegación por teclado y lectores de pantalla en elementos principales.
• Respetar prefers-reduced-motion.
• Revisar contraste.
• Ejecutar lint, tests disponibles y build.
• Corregir errores antes de finalizar.

12. Criterios de aceptación

La tarea se considera completada cuando:

☐ La identidad visual coincide con el brand guide de Cloak Studio.
☐ La web explica claramente los tres servicios.
☐ Cada tarjeta tiene un CTA funcional.
☐ Los CTA preseleccionan el servicio en el formulario.
☐ El formulario incluye los campos comunes.
☐ Los campos específicos cambian según el servicio.
☐ La validación funciona en cliente y servidor.
☐ El estado de éxito solo aparece tras confirmación real.
☐ Los errores se muestran de forma clara y no borran los datos.
☐ No hay emails, clientes, testimonios o proyectos inventados.
☐ La web funciona en móvil, tablet y desktop.
☐ Se puede navegar con teclado.
☐ No hay errores de build ni enlaces rotos.
☐ La integración de email está documentada y no se simula en producción.
☐ Se documentan las variables de entorno y los pasos de despliegue.

13. Instrucción final para Claude Code

Actúa como un equipo senior de diseño de producto, branding y desarrollo frontend/full-stack.

Implementa la web comercial de Cloak Studio siguiendo este documento y el archivo cloak-studio-brand-guide-claude-code.md.

No empieces instalando dependencias ni reescribiendo el proyecto sin inspeccionarlo. Primero analiza el repositorio y presenta un plan de trabajo. Después implementa por fases, verificando cada parte.

Prioriza una experiencia visual premium, mensajes comerciales claros, una sección de servicios convincente y un formulario inteligente que genere solicitudes útiles.

No inventes datos de contacto, clientes, proyectos, resultados ni credenciales. Si falta una integración o información del propietario, deja la funcionalidad preparada y documenta exactamente qué falta para activarla.

Al terminar, entrega un resumen de:

• Archivos creados o modificados.
• Componentes implementados.
• Cómo funciona el formulario.
• Variables de entorno necesarias.
• Comprobaciones realizadas.
• Pendientes que requieren información o credenciales del propietario.
